# 项目节点实施与验收计划

> 初始化模板：请根据具体项目填写，不要把方括号内容当作已完成结果。已有项目已有同类计划时，先合并现有记录，不能重置已有状态。

项目目标、总体思路、技术选择、数据来源、架构与实现方法见 [项目思路与技术方案](项目思路与技术方案.md)。如果目标项目沿用已有方案文件，应把本链接改为其实际路径；本文件专门维护逐节点实施、测试与验收结果。

## 2 执行规则

1. 每次开始、恢复或分配实现工作前，先读项目`AGENTS.md`、项目思路文档、本文件总规则、当前节点、相关设计和前置验收结果，检查Git状态。
2. 一次只实现用户明确授权的一个节点；未获授权的下一节点保持原状。必要的共享模块修复可在本节点范围内完成，受影响的已验收功能需要回归。
3. 完成当前节点后，按标准实施测试，真实回填本节点结果及总表状态，小步提交并按已授权范围处理推送，然后停止等待用户验收。
4. 自测通过与用户验收通过分开记录；用户验收通过不自动授权下一节点。必需测试未执行、跳过或失败不能标为通过。
5. 发现目标、验收标准或范围确需变更时，说明原因和影响并取得用户确认；不通过删测试、降标准或捏造数据使其通过。
6. 项目思路或实现发生实质变化时，同步维护方案文档和当前节点的内容；实施中发现影响未来节点时说明影响，未经用户确认不改未来节点。文件版本和变更历史通过Git管理；结果摘要和证据索引写在本文件对应节点，原始大文件放在项目约定的产物位置，不因每次修改额外复制备份。

## 5 节点详情模板

复制本节为每个真实节点建立独立章节，替换占位内容。不要在规划阶段创建尚未授权的源码或测试文件。

### Nxx：【节点名称】

**目标和前置：**【解决什么问题，前置节点、数据、环境及用户授权要求】。

**本节点实现范围：**【功能、模块、主要文件或接口、输入、输出；允许修改的共享内容】。

**实现方法与关键参数：**【算法或处理步骤、技术选择、配置及单位；说明哪些是建议、哪些待实测】。

**验收标准：**

- 【接口/功能正确性：写成可以判断通过或失败的要求】。
- 【测试输入、操作步骤、期望输出和明确断言；必要时写容差、边界及异常情况】。
- 【性能或业务效果的衡量方法、单位与样本；具体阈值尚未确定时写明冻结时间、依据和责任人，不编造数字】。
- 【适用的回归、人工验证、跨环境或真实服务检查；区分必需和可选】。

**预期效果与证据：**【用户能看到或使用什么；保存哪些日志、截图、配置、产物或可复核路径】。

**边界与停止位置：**【本节点不包含的后续能力；完成后等待用户验收】。
