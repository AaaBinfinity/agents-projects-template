# 开发与Git协作规范

本规范适用于采用本模板的项目。项目已有的约定先阅读后合并；用户对当前任务的明确要求优先。节点执行以 [项目节点实施与验收计划](项目节点实施与验收计划.md) 为入口。

## 1 工作流程

1. 阅读项目背景、现有文档与代码、适用的`AGENTS.md`和节点计划；检查Git分支、已暂存/未暂存改动及相关验收结果。
2. 确认用户指定的当前节点及范围，先说明交付和测试，然后实施该节点；不提前实施下一节点。
3. 按功能和模块拆分小改动，完成必要测试后检查差异，选择具体文件或差异块暂存并及时提交。不要提交无关文件，也不要为了数量制造不能复核的空提交。
4. 在同一节点计划回填实际结果和证据；区分代码版本、测试结果、自测结论与用户验收。节点完成后停止，等待用户验收和下一项授权。
5. 按已明确的权限处理推送；未授权推送时保留本地提交。交付时报告真实测试、局限、提交和推送状态。

## 2 提交格式

采用以下结构，方括号表示可选部分，实际提交时不写方括号：

```text
<type>[(scope)][!]: <description>

[body]

[footer]
```

`type`和`description`必填。类型为小写英文；scope、描述、正文和页脚以中文为主，专有名词、项目标识和必要标准语法可以使用英文。

| type | 用途 | 示例 |
| --- | --- | --- |
| `feat` | 新功能 | `feat(登录): 添加用户登录功能` |
| `fix` | 修补错误 | `fix(数据): 修正空值处理` |
| `docs` | 文档修改 | `docs(计划): 补充节点验收标准` |
| `style` | 不影响运行的代码格式调整 | `style(接口): 统一代码缩进` |
| `refactor` | 不新增功能、不修复Bug的重构 | `refactor(服务): 拆分配置解析逻辑` |
| `perf` | 性能优化 | `perf(查询): 减少重复数据读取` |
| `test` | 新增或修改测试 | `test(接口): 覆盖无效输入` |
| `build` | 构建流程或外部依赖 | `build(环境): 配置项目依赖` |
| `ci` | CI/CD配置或脚本 | `ci(检查): 添加自动化测试任务` |
| `chore` | 其他辅助性杂项 | `chore(仓库): 忽略本地缓存` |
| `revert` | 回滚提交 | `revert(接口): 回滚请求格式变更` |

- scope可省略；存在时描述模块或影响范围，如`数据`、`登录`、`api`。
- 描述简短明确，以动作词开头，如“添加、修复、统一”；英文描述用`add`、`fix`等动词原形并以小写开头，专有名词保留标准拼写。末尾不加句号，避免只写“更新”“修改”“完成”。
- 正文可说明动机、前后行为、重要取舍及真实验证/限制；没有正文时省略。标题、正文和页脚之间使用空行。
- 实际存在不兼容变更时，在标题使用`!`或在页脚写`BREAKING CHANGE: 中文说明`，并说明影响和迁移方法。实际关联Issue时可写`Closes #123`或`Fixes #123`；不要虚构Issue或破坏性变更。
- 文档修改选`docs`，格式调整选`style`，构建依赖选`build`，CI配置选`ci`，根据实际变更选择类型。

## 3 仓库、分支与推送

已有仓库先核对当前分支、远程及工作区；新仓库根据项目要求初始化并设置忽略规则。可继续使用合适的既有分支；新建分支按项目要求命名，没有项目专属要求时可用`binfinity/`前缀。

提交前可用`git status`、`git diff`和`git diff --cached`检查实际状态。用户明确授权推送后，先核对远程、分支和差异，再正常推送并检查远端；没有授权时保留本地提交。不要将原始大数据、模型权重、凭据、虚拟环境及不应入库的日志提交到普通Git。

未经明确授权，不强制推送、不改写已发布历史、不删除远程分支或用户的已有修改。用户明确要求修订旧提交时，先核对远程、分支、引用和签名；带签名的提交不能同时修改消息并保留原签名，按实际情况处理。确需覆盖已推送历史时，必须在授权范围内使用与已核对远端提交绑定的`--force-with-lease`；发现远端变化或保护规则拒绝时停止覆盖。

## 4 文档和证据

项目计划、接口及使用说明维护为当前有效内容；节点的实际结果写回节点计划。Git保存版本历史，不默认建立`history`目录、更新记录或逐次备份。项目已有必须保留的历史材料或用户另有明确要求时，遵循实际要求。

测试、实验、人工检查和线上运行分别按真实证据记录。保存不可变代码提交/源码哈希、环境、输入/配置版本、实际命令、测试结果与产物路径。待测、跳过、失败不得记为通过。
