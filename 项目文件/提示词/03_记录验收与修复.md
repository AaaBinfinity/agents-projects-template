# 提示词：记录验收与修复

根据实际情况选用下面的一段，填好节点编号和结论。只选择用户已经确认的事实；不要预先让AI填写验收通过。

## 记录验收通过

```text
我已验收项目【项目名称】的【节点编号】，结论为通过。
验收依据或补充说明：【填写；没有可写“按本次提交的结果验收”】。

请先读取该节点的计划、实际结果及Git状态，在同一节点计划中记录我的验收结论和日期，更新总表，并按项目Git规范提交相关文档；推送权限为【允许／不允许】。如果节点结果与上述结论存在事实冲突，请指出具体问题，不要自行编造测试结果。

本消息只授权记录本次验收，不授权开始下一节点。完成后停止。
```

## 验收不通过并修复当前节点

```text
我验收项目【项目名称】的【节点编号】不通过，具体问题如下：
【列出问题、复现方式及期望结果】

请先阅读项目协作约定、该节点计划、原有测试与实际结果，记录本次验收意见；只修复当前节点内上述问题及必要的相关缺陷，补跑必需测试和受影响的已验收功能回归。将真实修复、测试结果、失败与证据回填同一节点，按项目Git规范小步提交；推送权限为【允许／不允许】。

不要改变尚未授权的下一节点，也不要把修复后的自测通过直接写成我已验收通过。完成后停下，等待我再次验收。
```
